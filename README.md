## Вариант 1.2. Англо-русский словарь

Класс `Vocabulary` хранит пары «английское слово → перевод» в двоичном
дереве поиска. Английское слово является ключом, поэтому поиск, вставка и
удаление выполняются за время, пропорциональное высоте дерева.

Реализованные возможности:

- загрузка словаря из текстового файла в формате `слово:перевод`;
- добавление пары оператором `+=`;
- удаление слова оператором `-=` (включая удаление узла с двумя потомками);
- поиск и замена перевода через `operator[]`;
- подсчёт количества слов;
- полная очистка словаря и освобождение памяти в деструкторе;
- глубокое копирование при присваивании;
- собственные исключения `FileOpeningFailedException` и
  `WordNotFoundException`;
- консольное меню: загрузка файла, добавление, поиск, удаление, просмотр
  количества слов.

Основные файлы:

- `vocabulary/include/vocabulary.hpp` — объявления `WordPair` и `Vocabulary`;
- `vocabulary/src/vocabulary.cpp` — реализация дерева и операций словаря;
- `vocabulary/src/main.cpp` — консольный интерфейс;
- `vocabulary/src/unit_tests.cpp` — модульные тесты;
- `vocabulary/Doxyfile` — конфигурация генерации документации.

## Вариант 1.5.1. Крестики-нолики

Класс `TicTacToe` реализует игру для двух игроков на квадратном поле
произвольного размера. Первым ходит игрок `X`, затем ходы чередуются.

Реализованные возможности:

- создание поля размера `N × N`;
- проверка допустимости хода: координаты должны быть в пределах поля,
  клетка — свободна, игра — не завершена;
- установка значения клетки и получение текущего состояния поля;
- проверка победы по строке, столбцу и обеим диагоналям;
- определение ничьей при заполненном поле;
- форматированный вывод поля для консоли;
- определение текущего игрока;
- конструктор копирования и оператор присваивания;
- собственные исключения `InvalidMoveException` и
  `GameNotStartedException`;
- консольное меню для игры.

Основные файлы:

- `tic-tac-toe/include/tic_tac_toe.hpp` — объявление класса `TicTacToe`;
- `tic-tac-toe/src/tic_tac_toe.cpp` — логика игры;
- `tic-tac-toe/src/main.cpp` — консольный интерфейс;
- `tic-tac-toe/src/unit_tests.cpp` — модульные тесты;
- `tic-tac-toe/Doxyfile` — конфигурация генерации документации.

## Сборка и запуск

Для сборки нужны компилятор C++11, `make` и библиотека UnitTest++:

```bash
# Debian/Ubuntu
sudo apt-get install build-essential libunittest++-dev
```

### Словарь

```bash
cd vocabulary
make                 # собирает приложение и тесты
./vocabulary         # консольное меню
make tests && ./unit_tests
```

### Крестики-нолики

```bash
cd tic-tac-toe
make
./tic_tac_toe
make tests && ./unit_tests
```

### Документация

```bash
cd vocabulary   # или cd tic-tac-toe
make docs
# результат: docs/html/index.html
```

Для генерации документации требуется `doxygen` и `graphviz`.

## Тесты и покрытие

Тесты написаны на UnitTest++ и запускаются из консоли. Проверяются
граничные случаи: пустые структуры, отсутствующие элементы, удаление
корня и узлов с одним/двумя потомками, победы по всем линиям, ничья,
некорректные ходы, копирование и присваивание.

Локальный замер покрытия:

```bash
cd vocabulary
g++ -std=c++11 -Wall -Wextra -Werror -Iinclude --coverage \
    -o unit_tests src/unit_tests.cpp src/vocabulary.cpp -lUnitTest++
./unit_tests
gcovr --root . --filter 'include/' --filter 'src/vocabulary.cpp' \
      --fail-under-line 90 --print-summary
```

Аналогично для `tic-tac-toe`, где вместо `src/vocabulary.cpp` указывается
`src/tic_tac_toe.cpp`.

## CI/CD

Workflow `.github/workflows/ci.yml` запускается при push в `main`, при
pull request и при создании тега `v*`. Он выполняет:

1. **build-test** — сборка обоих проектов с `-Wall -Wextra -Werror`,
   запуск тестов и проверка покрытия `gcovr` с порогом 90 %;
2. **static-analysis** — статический анализ `clang-analyzer` через
   `clang-tidy` и строгая проверка компиляции с `-Wpedantic -Werror`;
3. **docs** — генерация HTML-документации Doxygen и публикация её как
   артефакта сборки;
4. **package** — сборка релизных бинарников, упаковка в архивы и
   сохранение артефактов;
5. **release** — при push тега `v*` архивы автоматически прикрепляются к
   GitHub Release.

Скачанный из Releases архив содержит готовый исполняемый файл и README,
поэтому программу можно запустить без сборки проекта:

```bash
tar -xzf vocabulary-linux-x86_64.tar.gz
./vocabulary
```
